# Экономика НАТБИРЖИ: измеримые условия баланса

Работа авторизована пользователем: самостоятельно переработать всю экономику,
сохранить индивидуальные отрасли и проверить реальные потоки. Дополнительное
согласование проекта не требуется по его ранее указанному правилу «делай как знаешь».

## Критерии

- Сравнивать предприятия по полной стоимости капитала (cash + строительные и
  проектные материалы), прибыли после 13% налога, одинаковому месту в отрасли
  и уровню. Стартовое предприятие: 10 часов в нормальном рынке; поздние дольше.
- Стоимость каждой следующей ступени учитывается в общей инвестиции. Улучшения
  увеличивают абсолютную прибыль и постепенно сокращают полную окупаемость.
- Сырьё растёт вместе с выпуском; максимальная экономия на единицу продукции
  за 50 уровней ограничена 25%. Премиальные бонусы рассматриваются отдельно.
- Калибровка физических рецептов использует постоянные базовые цены, не цены
  активного кризиса. Никакой дополнительной эмиссии cash при производстве на склад.
- Нормальная торговля игроков прибыльна для всех предприятий/уровней, резерв
  остаётся дорогим аварийным вариантом. Сырьё/выручка/накопления не дублируются.
- Логистика имеет повторяющееся потребление; конечным товарам нужен явный
  внешний потребитель. Нельзя делать вид, что весь выпуск гарантированно продан.
- Legacy API проверяется наравне с V2: отсутствие экрана не закрывает endpoint.
- Сохраняются правила пользователя: вода 2 cash; кредит 20% в сутки, до 5 дней,
  до 50% NAV с одобрением; налоговая база — чистая прибыль компании за закрытый
  12-часовой период, ставка 13%; налог обязателен при закрытии периода, производство
  сразу останавливается при неоплате, а простой штраф 3% от основного налога
  начисляется за каждый полный час просрочки.

## Порядок

1. Сохранить baseline через `scripts/natbirzha_economy_audit.py`: все 108×50
   состояний, нормальные/NPC/стрессовые цены, отдача инвестиций и поток ресурсов.
2. В `catalogs/businesses/balance.py` построить единый статический профиль
   производительности; `business_rates.py` использует этот же профиль при реальном
   settlement. Общая стоимость улучшений берётся из общей функции с quote API.
3. Ввести необходимые логистические/сервисные потребности, обновить UI оценок
   (рыночная прибыль и отдельно резервный сценарий), сохранять реальные остатки.
4. Исправить доказанные ошибки финансовых потоков, снабжения и legacy production
   после независимых аудитов. Отдельные файлы для независимых обязанностей.
5. Регрессионные тесты: все уровни, границы инвестиций/налогов, реальные inventory
   и cash, дробные операции, торговые пары, offline/idempotency. Затем полный
   tests/natbirzha и обязательный tests/test_suite.py, frontend, syntax.
6. Сохранить after-отчёт и пояснить реальные пределы модели (ликвидность рынка,
   состав игроков и добровольные цены). Интегрировать новые remote-коммиты,
   коммит/обычный fast-forward push main/dev на все три remote после проверки.
